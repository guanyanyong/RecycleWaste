## 过磅工作台改造：多车并行（在场工单）

- 需求：原工作台一次只能作业一张工单，现场需同时进行 3~5 辆车的过磅。
- 后端（数据模型本就支持，只需补接口与约束）：
  - `weigh_repo.active_trips()`：单次聚合查询（`case when` 计数）返回 status in (0,1) 行程及各阶段进度，避免 N+1。
  - `weigh_repo.count_active_trips()` / `find_active_by_plate()`。
  - `weigh_service.list_active_trips()`、`cancel_trip()`；`create_trip` 新增 `_guard_parallel_capacity`（MAX_ACTIVE_TRIPS=12）与 `_guard_plate_duplicate`（同车牌不可并存未结束工单）。
  - 路由：`GET /weigh/trips/active`（必须声明在 `/trips/{trip_id}` 之前）、`POST /weigh/trips/{id}/cancel`。
- 前端 `views/WeighWorkbench.vue` 重写：在场工单卡片队列（横向滚动 + 滚轮 + 左右箭头 + 右缘渐隐，新开一单固定在右侧不随列表滚动）、按 `trip_id` 的独立录入草稿、12s 轮询（弹窗/写操作时暂停）、选中卡自动滚入视区、工单完结自动接管下一张。
- 新增脚本 `backend/scripts/seed_active_tickets.py`：生成 5 张不同阶段的在场工单（空单/待核价/待皮重/待结算/单次过磅）。
- `smoke_test.py` 车牌改为时间戳唯一值，避免与在场工单重复校验冲突。
- 验证：无头 Chrome 跑通 开单→加货→核价→皮重→重复车牌拦截(409)→空单作废→14s 轮询，控制台 0 报错；冒烟测试与前端 build 均通过。
- 布局基准：1440×900 下明细卡底边刚好贴合视口（表格高 = vh-688）。

## 新增「过磅工作台-触摸」零键盘终端

- 需求：磅房有操作员不会用电脑但会用触摸屏，要求新建菜单「过磅工作台-触摸」，所有输入可用触摸完成。
- 路由 `/touch`（顶层，全屏独立布局不套控制台侧边栏），`meta.perm = weigh:create`；`MainLayout` 侧边栏新增「现场终端」区块入口 `.term-entry`。
- 新增组件：
  - `components/touch/TouchKeypad.vue`：mode = decimal/int/phone/plate；内部 `inner` 缓冲避免连点丢字符；正则增量校验（decimal `^\d{0,4}(\.\d{0,2})?$`、plate `^[\u4e00-\u9fa5]?[A-Z0-9]{0,7}$`，省份汉字必须放行）；右侧固定「退格/清空/确定」竖列。
  - `components/touch/TouchSheet.vue`：Teleport 全屏遮罩面板（normal/wide）。
- 页面 `views/TouchWorkbench.vue`：panel 状态机 newTrip → trip → material → weight → price → tare → receipt；左侧在场车辆大卡（240×102），右侧大屏读数（44~82px）+ 键盘；15s 轮询仅在 trip 面板且无弹层时刷新。
- 业务取舍：新客户只用手机号登记，姓名自动为「散客+尾号4位」（避免拼音/汉字输入门槛）；单次过磅核价后自动 complete；沿用上件皮重时只禁用数字键（保留确定），并额外给「使用该皮重·下一步」大按钮（原实现整体 pointer-events:none 导致无路可走，已修）。
- 验证：无头 Chrome 全触摸点击跑通 新客户登记→车牌键盘→两次过磅(16.28/6.50=9.78,扣0.29,结算9.49,¥20878)→单次过磅自动完成(8.88,¥22200)→沿用皮重(5.40)→有批次作废被 409 拦截→空单作废 12→11；控制台 0 报错；1440/1920 两档布局通过。
- 截图 `docs/touch-*.png`；文档新增 `10.5 触摸终端`，README 增加入口说明；`docs/dashboard.png` 已换为带触摸入口的新版。
